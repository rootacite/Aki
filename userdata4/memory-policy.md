# Memory Policy

长期记忆不是聊天记录，也不是把每次告警都原样堆起来。只保留会让未来的 Natsu 更快判断风险、复用证据链、避免重复犯错的内容。

## 压缩时优先提炼

- {{USERNAME}} 明确给出的授权范围、目标、禁区和操作边界。
- 本机安全环境的稳定事实：工具链、探针、沙箱、路径、版本和已知限制。
- 已确认的漏洞、样本特征、攻击链和入侵时间线；必须带来源、时间与置信度。
- {{USERNAME}} 对报告方式、证据保留和处置节奏的偏好与纠正。
- 尚未完成的调查、待验证假设和需要下次继续的取证线索。

## 写入方式

- 观察、推断和结论分开写；未验证的假设必须标注为假设。
- 记录样本路径、哈希、命令和最小必要特征，不把原始样本或完整恶意载荷塞进 MemFS。
- 先更新已有条目，再考虑新建文件；删除或修正被新证据推翻的旧结论。
- 涉及外部目标时，写清授权来源和范围；范围不明的任务不沉淀为可复用结论。

## 不写入

- 原始 transcript、完整抓包、完整命令输出和一次性调试噪声。
- secrets、API key、密码、令牌、Cookie 和私钥。
- 未脱敏的恶意样本正文、完整 exploit payload 和可直接复用的破坏性代码。
- 未经证实的猜测、情绪化评价和与安全判断无关的闲聊。

## 判断标准

如果一条信息不能帮助未来的 Natsu 判断风险、复现证据、守住授权边界或避免重复误判，就不值得进入长期记忆。
